# 1.6. Проверка отказов и защита данных

[Этап 1](task_1.md) · Зависит от [1.2](task_1_2_files.md), [1.4](task_1_4_repository.md) и [1.5](task_1_5_world_transfer.md).

## Результат

Неудачная операция не уничтожает рабочий мир, не публикует неполную версию и
не пишет за пределы выбранного каталога. Пользователь понимает, как повторить операцию.

## Прогресс

- [x] Есть тесты обрыва и повреждения объектов с повторной передачей.
- [x] Есть тесты незавершённого переключения и защиты неопубликованных изменений.
- [x] Есть проверки опасных путей, символических ссылок и размеров сообщений.
- [x] Отказ записи объекта проверяется через подмену записи: старая версия сохраняется, повтор возможен.
- [ ] Проверить и при необходимости дополнить сценарии отказа записи при сборке и переключении, а не только при сохранении объекта.
- [ ] На тестовом ограниченном томе проверить реальное исчерпание места; записать состояние до сбоя и после повторного запуска.
- [ ] Проверить отмену и принудительное завершение в разных фазах; после перезапуска нет зависших блокировок, текущий мир определён однозначно.
- [ ] Проверить понятность сообщений и инструкций повторного запуска для каждого отказа; записать результаты и известные ограничения.

## Где смотреть и проверять

`WorldRepositoryTest`, `WorldTransferTest`, тесты `transfer/resume`,
`FrameCodecTest`, `DesktopOperationsTest`, `MinecraftSavesTest`.

```bash
./gradlew :core:test :cli:test :desktop:test
```

Тест с искусственным отказом записи не равен проверке физически заполненного
диска. Повторять такие проверки следует на отдельном тестовом томе и копии мира.
Результаты и окружение записать рядом с [ручной приёмкой](../docs/manual-acceptance.md).
