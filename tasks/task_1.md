# Задача 1. Передача актуальной версии мира

README описывает общую картину EnderLink. Этот документ определяет первую самостоятельную задачу: утилиту для передачи сохранения Minecraft Java Edition между компьютерами с отправкой только недостающих данных.

## Цель и сценарий

Пользователь закончил играть, закрыл мир или остановил сервер и опубликовал новую версию сохранения. Другой пользователь получил эту версию и продолжил играть на своём компьютере.

Миры могут занимать десятки гигабайт и больше, поэтому повторная передача всего мира после каждой игровой сессии нежелательна. При первом получении передаются все отсутствующие данные; при последующих — только изменения относительно имеющихся данных.

## Объём первой версии

- Работа с каталогом закрытого мира.
- Публикация версий мира с уникальным идентификатором и ссылкой на родительскую версию.
- Передача между двумя компьютерами по доступному сетевому адресу, сначала в локальной сети.
- Передача новых данных и учёт удалённых файлов.
- Проверка целостности, докачка после обрыва и сохранение предыдущей рабочей версии.
- CLI с прогрессом и понятными сообщениями об ошибках.
- Обнаружение независимых изменений одного мира на разных компьютерах.

GUI, управление Minecraft-сервером, игровые туннели, NAT traversal, relay и автоматическая передача роли хоста относятся к следующим задачам.

## Как передавать изменения

Первый промежуточный прототип может сравнивать файлы и передавать изменившиеся целиком. Целевой результат задачи — передача на уровне блоков: изменение части большого файла не должно автоматически требовать передачи всего файла.

Предлагаемый процесс:

1. Отправитель фиксирует согласованную версию закрытого мира.
2. Создаёт манифест: пути файлов, размеры, хеши и описание блоков.
3. Получатель определяет, какие данные уже есть локально, и запрашивает недостающие.
4. Новая версия собирается отдельно от текущей рабочей копии.
5. Проверяются целостность и полнота новой версии.
6. Только после успешной проверки версия становится доступной для игры.

Манифест задаёт полный состав версии, поэтому удалённые файлы не должны оставаться в новой копии. Прерванная передача не должна делать неполную версию текущей.

Конкретный алгоритм разбиения на блоки, размер блоков, формат манифеста и транспорт выбираются при реализации. Начать можно с фиксированных блоков и криптографических хешей; эффективность при смещении данных внутри файлов нужно измерить отдельно. Понимание внутреннего формата Minecraft для базовой передачи не требуется.

Экономия трафика не означает отсутствия дисковых затрат: поиск изменений может потребовать чтения больших файлов. Необходимо отдельно измерять время сканирования, объём передачи и дополнительное место на диске. Не следует загружать весь мир в оперативную память.

## Согласованность и сохранность данных

### Закрытый мир

Для первой версии пользователь обязан выйти из мира или остановить сервер до публикации и не открывать его до завершения фиксации версии. Обычное копирование файлов во время игры не гарантирует согласованное сохранение.

Опубликованные данные должны оставаться неизменными на время передачи. Способ фиксации снимка и защита от изменений источника определяются при реализации; одной проверки времени изменения файлов для гарантии недостаточно.

### Сбои и восстановление

- При обрыве уже проверенные полученные блоки сохраняются для докачки.
- Повреждённые данные обнаруживаются по хешам и не активируются.
- Предыдущая рабочая версия сохраняется до успешного завершения обновления.
- Сбой процесса во время переключения версии должен допускать восстановление после перезапуска.
- Нехватка места должна завершать операцию понятной ошибкой без повреждения рабочей копии.
- Полученные пути проверяются: запись за пределы целевого каталога запрещена; обработка символических ссылок должна быть явно определена.
- Сетевой доступ должен требовать явного разрешения получателя; способ аутентификации и защиты соединения определяется до испытаний вне доверенной среды.

### Независимые изменения

У версии есть идентификатор и родитель. Если два пользователя продолжили играть независимо от одной версии, утилита сообщает о расхождении и сохраняет обе ветки. Выбирать актуальную ветку только по времени файлов нельзя.

Автоматическое объединение игровых миров в задачу не входит. Правило первой версии: одна выбранная ветка продолжения игры, явный выбор при конфликте.

## Структура реализации

- `core`: манифесты, версии, хеширование, сравнение, сборка и проверка сохранений; логика обмена данными.
- `cli`: команды пользователя, настройки, прогресс и ошибки.
- `agent`: подключается при необходимости фоновых передач; постоянный процесс не является обязательным для первого прототипа.

Логику работы с версиями следует отделить от сетевого транспорта, чтобы сначала проверить её на двух локальных каталогах.

## Этапы

1. **Локальные версии.** Создание манифеста закрытого мира, сравнение двух каталогов, сборка и проверка новой версии с сохранением предыдущей.
2. **Обмен между двумя процессами.** Передача манифеста и изменившихся файлов по доступному адресу. Это промежуточный прототип.
3. **Передача блоков.** Повторное использование локальных блоков, запрос недостающих, проверка хешей и докачка.
4. **Устойчивость и конфликты.** Восстановление после сбоя, недостаток места, удаление файлов, независимые ветки и защита путей.
5. **Испытания на реальных мирах.** Проверка открытия полученного мира и замеры на целевых ОС и размерах сохранений.

## Критерии готовности

- [ ] Мир впервые передаётся на другой компьютер и открывается в совместимой версии Minecraft.
- [ ] После следующей игровой сессии получатель получает точное содержимое опубликованной версии, включая удаления.
- [ ] Неизменившиеся данные повторно не передаются; для частично изменённого большого файла передаются недостающие блоки.
- [ ] При одинаковых версиях передаются только необходимые метаданные.
- [ ] Передача продолжается после обрыва с повторным использованием проверенных блоков.
- [ ] Повреждённые или неполные данные не становятся рабочей версией.
- [ ] Предыдущая рабочая версия доступна после неудачного обновления.
- [ ] Независимые изменения обнаруживаются без молчаливой перезаписи одной из веток.
- [ ] Есть проверки обрыва, перезапуска, нехватки места и небезопасных путей.
- [ ] Измерены время сканирования, объём передачи, потребление памяти и дополнительное место на диске на реальных мирах.

Процент экономии трафика заранее не фиксируется: он зависит от характера изменений. Для проверки нужны отдельные случаи без изменений, с локальными правками существующего мира и с большим объёмом новых данных.
