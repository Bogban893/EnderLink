# Пользовательские задачи и улучшения

Пункты B01–B17 соответствуют номерам из списка команды. `[x]` означает выполненный
критерий с указанным основанием; `[ ]` — работу или проверку впереди. Наличие части
механизма не закрывает пользовательский сценарий. Статусы сверены с кодом
24 ноября 2026 года; CI отмечен по сообщению пользователя, тесты здесь не перезапускались.

Ближайшая цель — удобная и надёжная передача одиночных миров. Выбран общий
процесс агента: CLI и GUI отправляют ему команды и получают события об изменениях.
Запуск отдельного Minecraft-сервера без активного участия хоста, игровой туннель
и управляемая миграция сервера отложены. Интернет-передача миров через свой сервер
обнаружения остаётся отдельной задачей.

- [ ] При подключении интерфейс получает актуальный снимок состояния, затем события; после переподключения восстанавливает актуальное состояние.
- [ ] Подключить CLI и GUI к одному процессу, показывать изменения от любого клиента в обоих интерфейсах.
- [ ] Определить конфликты команд и отмену: изменение одного мира сериализуется, повтор команды не создаёт вторую передачу, клиент видит занятую операцию.
- [ ] Проверить закрытие одного интерфейса, повторное подключение и одновременные команды без потери состояния и повреждения данных.

Сейчас `IrohProfile` блокирует один профиль между процессами. Блокировку сохраняем:
ею владеет агент, а интерфейсы работают через него. Направление `cli/desktop → agent → core`
подтверждено; одних зависимостей Gradle недостаточно — нужен локальный API к общему
процессу. Удаление модуля `agent` больше не является текущим планом.

## B09. Предварительная передача во время игры

- [ ] После завершённого снимка передавать новые блоки в фоне, объединять частые события и ограничивать нагрузку на диск и сеть.

- [ ] Измерить пользу по времени финальной передачи и стоимость по диску/CPU/сети.

Статус «передача по ходу» означает подготовку данных. Он не гарантирует готовую

сохранение» не фиксируется как решение до исследования.
