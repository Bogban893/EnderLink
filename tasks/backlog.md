## B09. Предварительная передача во время игры

Приоритет: исследование/позже; не блокирует обычную передачу закрытого мира.

Решение пользователя: только Vanilla, без плагина/мода и без зависимости от
снимков файловой системы. В текущем `VanillaServer` есть штатное сохранение и
остановка, но нет подтверждённого согласованного снимка *во время* игры.
`save-off` само по себе не останавливает все записи данных игроков (см.
[сообщение в баг-трекере Mojang](https://bugs.mojang.com/browse/MC-217729)); копирование
открытой папки нельзя выдавать за безопасную фоновую версию. До появления
проверяемого механизма снимка B09 остаётся исследованием; реализация фонового
копирования и публикации не включается в пользовательский путь.

- [ ] Выбрать способ получения согласованного снимка: управляемый сервер, механизм снимков или интеграция с игрой; простое наблюдение за файлами согласованность не обеспечивает.
- [ ] После завершённого снимка передавать новые блоки в фоне, объединять частые события и ограничивать нагрузку на диск и сеть.
- [ ] Хранить на получателе неподтверждённые данные отдельно; открывать для игры только целиком проверенную версию.
- [ ] При окончательной передаче роли выполнить финальное согласованное сохранение и передать остаток; при сбое фона оставить последнюю подтверждённую версию.
- [ ] Измерить пользу по времени финальной передачи и стоимость по диску/CPU/сети.

Статус «передача по ходу» означает подготовку данных. Он не гарантирует готовую
резервную копию каждого изменения. Копирование живого мира «на каждое маленькое
сохранение» не фиксируется как решение до исследования.
