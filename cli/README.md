# Чат и передача файлов и каталогов

## Версии закрытого мира

Закройте мир в Minecraft или остановите сервер до публикации и не меняйте его во время команды. Создайте отдельное хранилище и опубликуйте исходный каталог:

```bash
./cli/build/install/cli/bin/cli world-publish --source "./saves/Мой мир" --repository ./my-world-repo
./cli/build/install/cli/bin/cli world-status --repository ./my-world-repo
```

В `my-world-repo/world` лежит проверенная рабочая копия, а история и объекты — в `my-world-repo/.enderlink`. После следующей игровой сессии повторите `world-publish` с тем же исходным миром. Если играете прямо в `my-world-repo/world`, укажите этот путь как `--source`.

Получатель запускает:

```bash
./cli/build/install/cli/bin/cli world-receive --repository ./friend-world-repo --port 25570
```

Отправитель запускает:

```bash
./cli/build/install/cli/bin/cli world-send --repository ./my-world-repo --host 127.0.0.1 --port 25570
```

Для следующей отправки закрытого мира можно совместить публикацию и передачу:

```bash
./cli/build/install/cli/bin/cli world-send --source "./saves/Мой мир" --repository ./my-world-repo --peer друг
```

`--source` обновляет версию в указанном репозитории перед подключением к получателю. Если версия уже опубликована, опустите параметр. Получатель по-прежнему запускает `world-receive`; при повторе после обрыва используйте те же каталоги. Не открывайте мир в Minecraft во время публикации.

При публикации и `world-status` CLI проверяет структуру `level.dat` и оба расположения файлов игроков (`playerdata` и `players/data`). Если найдены встроенные данные владельца старого одиночного мира, появится предупреждение: перед основной игрой проверьте его инвентарь на выделенном сервере. Само предупреждение не меняет файлы мира.

Для старого одиночного мира, где профиль владельца хранится в `level.dat`, один раз создайте серверный файл владельца по UUID его Minecraft аккаунта:

```bash
./cli/build/install/cli/bin/cli world-publish --source "./saves/Мой мир" --repository ./my-world-repo
./cli/build/install/cli/bin/cli world-import-owner --repository ./my-world-repo --owner-uuid 123e4567-e89b-12d3-a456-426614174000
./cli/build/install/cli/bin/cli world-send --repository ./my-world-repo --peer друг
```

Укажите настоящий UUID владельца, а не пример из команды. Импорт создаёт новую версию внутри репозитория, не меняет исходный одиночный мир и не перезаписывает существующий файл игрока. После импорта отправляйте эту версию **без** `--source` исходного одиночного мира; публикация исходника без нового файла игрока будет остановлена. Для миров с `players/data` (Minecraft Java 26.1+) этот импорт не нужен. На совместимом тестовом сервере проверьте инвентарь владельца при первом входе.
Если внешний исходный каталог потерял файл игрока, публикация остановится до изменения активной версии. Переход `playerdata/<UUID>.dat` → `players/data/<UUID>.dat` допускается при сохранении того же UUID.

Для iroh используйте `world-receive --repository ./friend-world-repo --iroh` и `world-send --repository ./my-world-repo --peer друг` после настройки друзей командами `id` и `add`. Можно указать `--relay` отправителю и `--peer` получателю. Каждая команда обслуживает одну попытку; при обрыве снова запустите обе команды с теми же каталогами. Проверенные блоки повторно не отправляются. Сначала передаётся полный манифест, затем только отсутствующие блоки; новая версия активируется после проверки всего дерева. Существующая рабочая версия остаётся доступной в `.enderlink/previous`, а старые данные — в хранилище объектов.

Если обе стороны изменили мир независимо, получатель сохранит обе полные ветки и сообщит о конфликте, оставив рабочую копию прежней. Для явного выбора другой ветки используйте `world-checkout --repository ./friend-world-repo --version sha256:<ID>`. Конфликт не объединяется автоматически. Текущая передача использует фиксированные блоки по 256 КиБ: небольшое изменение внутри большого `.mca` обычно требует один новый блок, а сдвиг байтов может затронуть многие. Запросы и подтверждения объектов объединены в группы до восьми блоков, чтобы уменьшить ожидание ответов на соединениях с задержкой. Обновите CLI на обеих сторонах: протокол `ELW4` несовместим с прежним `ELW3`. Для реальной передачи мира нужны совместимые версии Minecraft на обоих компьютерах; открытие полученной копии в игре следует проверить отдельно. TCP используйте только в доверенной сети: этот режим не шифрует и не аутентифицирует участников.

## Через интернет: iroh

```bash
./gradlew :cli:installDist
./cli/build/install/cli/bin/cli id
./cli/build/install/cli/bin/cli add друг ID_ДРУГА
```

На обоих компьютерах один раз обменяйтесь ID и добавьте друг друга. Профиль
по умолчанию тот же, что у `iroh-test`: `~/.enderlink/iroh-test`. Ранее созданные
ID, друзья и рабочие relay сохраняются. Другой каталог задаётся через
`--profile <каталог>` у каждой команды. Просмотр друзей: `cli friends`, удаление:
`cli remove друг`. Имена — локальные; ID подтверждается ключом при подключении.

Чат — на первом компьютере:

```bash
./cli/build/install/cli/bin/cli listen --iroh
```

На втором:

```bash
./cli/build/install/cli/bin/cli connect --peer друг
```

Приём файла или каталога:

```bash
./cli/build/install/cli/bin/cli receive --iroh --output ./received
```

Отправка на другом компьютере:

```bash
./cli/build/install/cli/bin/cli send --peer друг --file "./my world.zip"
./cli/build/install/cli/bin/cli send --peer друг --directory "./Мой мир"
```

Каждая команда обслуживает одну передачу: для следующей снова запустите
`receive`. Можно ограничить принимающую сторону определённым другом:
`receive --peer друг --output ./received` или `listen --peer друг`.
`--peer` автоматически выбирает iroh. `--host` и `--port` используются только с TCP.

Существующие SHA-256, прогресс, проверка путей и докачка работают поверх общего
интерфейса `Connection`. Для продолжения после обрыва перезапустите `receive`
с тем же `--output`, затем ту же команду `send`. Автоматического переподключения
пока нет. Целевой файл или каталог не перезаписывается.

Используются публичные сервисы поиска и relay iroh. Собственный сервер не нужен,
но доступ к этим сервисам необходим. Маршрут и его изменения выводятся в терминал:
`relay` означает пересылку через посредника, `напрямую` — прямой путь.
У публичных relay есть ограничения скорости и доступности.

Если поиск по ID не сработал, оставьте получателя запущенным и передайте его
текущий адрес из строки `Мой relay` отправителю:

```bash
./cli/build/install/cli/bin/cli send --peer друг --file "./my world.zip" --relay https://RELAY_ПОЛУЧАТЕЛЯ/
```

Замените адрес примером из вывода получателя. Та же опция доступна у `connect`.
Рабочий relay запоминается после успешного согласования соединения. Если он
устареет, выполняется попытка поиска по ID; при недоступном поиске понадобится
новый URL. Для подробных логов добавьте `--debug` на обеих сторонах.

Не меняйте VPN между запуском и подключением. Раздельное туннелирование позволяет
оставить мессенджер через VPN, а Java/EnderLink пустить напрямую. Влияние VPN
и смены сети зависит от маршрутизации; сохранённый ID от этого не меняется.

Обновляйте обе стороны: интегрированный транспорт использует новое согласование
режимов и несовместим со старым экспериментальным бинарником из тега
`p2p-experiments`. Чат, передача и диагностический стенд используют отдельные
режимы: если участники выбрали разные команды, соединение отклоняется до файловых данных.

## По локальному адресу: TCP

Собрать утилиту:

```bash
./gradlew :cli:installDist
```

В первом терминале запустить ожидание одного подключения:

```bash
./cli/build/install/cli/bin/cli listen --port 25570
```

Во втором терминале подключиться:

```bash
./cli/build/install/cli/bin/cli connect --host 127.0.0.1 --port 25570
```

Для проверки на двух компьютерах установить утилиту на обоих и заменить
`127.0.0.1` локальным IP принимающего компьютера. Принимающая сторона по
умолчанию слушает все сетевые интерфейсы; для проверки только на своём
компьютере можно указать `listen --host 127.0.0.1`.

## Передача одного файла

Режим выбирается при запуске. Для чата используются `listen`/`connect`, для
файла — `receive`/`send`. Обе стороны должны выбрать соответствующий режим.
Команды ниже выполняются после сборки `:cli:installDist`.

На получателе:

```bash
./cli/build/install/cli/bin/cli receive --output ./received --port 25570
```

На отправителе:

```bash
./cli/build/install/cli/bin/cli send --host 127.0.0.1 --port 25570 --file "./my world.zip"
```

Для другого компьютера заменить `127.0.0.1` его локальным IP. Каталог
получения создаётся автоматически. Файл получает исходное имя; существующий
файл с таким именем не перезаписывается. Каждая команда обслуживает один файл
и завершается. Чат и передачу можно запускать одновременно на разных портах.

Файл передаётся блоками по 256 КиБ без загрузки целиком в память. До подключения
отправитель вычисляет SHA-256 файла и блоков, поэтому сначала происходит полное
чтение с диска. Получатель хранит проверенные блоки в скрытом каталоге
`.enderlink-resume-<идентификатор>` внутри `--output`. При повторной попытке
сохранённые блоки заново проверяются по хешам. После получения всех блоков
файл собирается, проверяется SHA-256 и отправляется подтверждение. 100% прогресса
означает передачу байтов; успех отправитель сообщает после подтверждения.

Для `send --file` докачка включена автоматически. После обрыва CLI повторяет
подключение дважды; `--retries 0..5` задаёт число повторов. Получатель ждёт
повторное подключение до 30 секунд, после чего попытка считается неудачной.
Проверенные блоки сохраняются и повторно не передаются. Если попытки исчерпаны,
запустите `receive` с тем же `--output`, затем ту же команду `send --file`.
CLI показывает идентификатор операции и при повторном подключении принимает
только её продолжение. Отмена — Ctrl+C. Обновить CLI нужно на обеих сторонах.
Если файл уже опубликован, но подтверждение потерялось, повторная попытка
проверяет его размер и SHA-256 и завершает ту же операцию без второй копии.
После успеха блоки и метаданные версии удаляются. Служебный файл
`.enderlink-resume.lock` остаётся: это нормально; он предотвращает одновременную
докачку в один каталог. Во время сборки результата требуется место и под блоки,
и под полный файл. Прогресс включает блоки, уже имеющиеся у получателя.

Другая версия файла (даже с прежними именем и размером) не использует состояние
старой версии. Незавершённые состояния старых версий автоматически не удаляются.
Чтобы отказаться от докачки, после остановки обеих программ можно удалить
соответствующий каталог `.enderlink-resume-*`.

Таймаут ожидания входящих данных или ответа — 30 секунд; это не ограничение
общего времени передачи. Исходный файл нельзя изменять во время отправки.
Синхронизация изменений пока не поддерживается.

## Передача каталога

На получателе используется та же команда `receive`: она автоматически
определяет, отправлен файл или каталог. На отправителе выбрать `--directory`
вместо `--file`:

```bash
./cli/build/install/cli/bin/cli receive --output ./received
./cli/build/install/cli/bin/cli send --host 127.0.0.1 --directory "./Мой мир"
```

Команды выполняются в разных терминалах или на разных компьютерах. На
получателе появится `received/Мой мир` со всеми файлами, подпапками и пустыми
каталогами. Показывается общий прогресс по сумме размеров файлов. Каждый файл
проверяется по SHA-256. Передача завершается подтверждением всего дерева.
Нужна обновлённая сборка CLI на обоих компьютерах.

Докачка для `--directory` включена автоматически. Команды сами переподключаются
в пределах `--retries`. После исчерпания попыток повторно запустите `receive`
с тем же `--output` и ту же команду `send --directory`.
Сначала снова сканируются пути и вычисляются хеши всех файлов. Манифест
учитывает пути, типы элементов, размеры и SHA-256: порядок обхода диска
не влияет на идентификатор версии.

Данные сохраняются в `.enderlink-directory-<идентификатор>` внутри `--output`.
Подкаталог `tree` содержит готовые файлы и папки, `files` — состояния докачки
незавершённых файлов. При повторном запуске готовые файлы проверяются и не
передаются; для остальных запрашиваются только недостающие или повреждённые
блоки. Прогресс учитывает уже имеющиеся данные. Служебные файлы состояния
не попадают в итоговый каталог.

Под исходным именем дерево появляется только после полной проверки состава
и хешей. Существующий файл или каталог с таким именем не перезаписывается;
если дерево полностью совпадает с манифестом, повторная попытка подтверждает
успех без создания второй копии.
После успеха состояние этой версии удаляется, файл `.enderlink-directory.lock`
остаётся для безопасной блокировки следующих передач. При обрыве состояние
сохраняется. Для отмены докачки после
остановки программ можно удалить соответствующий `.enderlink-directory-*`.

Изменение состава или содержимого дерева создаёт отдельное состояние версии.
Старое незавершённое состояние сохраняется. Объединение разных версий и
использование файлов уже опубликованного каталога пока не реализованы.
Во время докачки требуется место под готовые файлы и блоки, а при сборке
очередного файла — также под его полную копию. Во время длительной проверки
хешей получатель отправляет служебные уведомления для поддержания соединения.

Передаётся всё содержимое, включая скрытые и пустые файлы. Символические
ссылки и специальные файлы отклоняются. Права доступа, владельцы и времена
файлов не сохраняются. Пока нет объединения с существующим каталогом
и отправки только изменений между разными версиями дерева.

Исходное дерево должно оставаться неизменным от начала сканирования до
окончания передачи. Для Minecraft нужно выйти из мира или остановить сервер:
обычное копирование файлов работающего мира не гарантирует согласованность.

## Работа чата

Вводимые строки отправляются собеседнику в UTF-8. `/quit` или конец
стандартного ввода закрывают соединение и завершают сессию. После отключения
собеседника процесс также завершается. Повторное подключение требует нового
запуска команды. Предел одного сообщения — 1 МиБ в UTF-8.

Можно запускать через Gradle в двух терминалах:

```bash
./gradlew --console=plain :cli:run --args="listen --port 25570"
./gradlew --console=plain :cli:run --args="connect --host 127.0.0.1 --port 25570"
```

Готовый скрипт из `installDist` удобнее для интерактивного ввода. В Windows
используются `gradlew.bat` и `cli.bat` из соответствующих каталогов. Нужна Java 21.

## Автодополнение в Bash

Из корня проекта подключить скрипт для текущего терминала:

```bash
source ./cli/completion/cli.bash
```

После этого Tab дополняет команды и подходящие им флаги, после `--file` —
пути к файлам и каталогам, после `--output` и `--directory` — только каталоги. Уже указанные
флаги повторно не предлагаются. Адрес и порт вводятся вручную.

Работает для `cli` из PATH, путей `./cli/build/install/cli/bin/cli` и
`cli/build/install/cli/bin/cli` от корня проекта, а также абсолютного пути
к собранному скрипту. Для другого пути или псевдонима нужно зарегистрировать
его явно, например `complete -F _enderlink_cli_complete my-cli`.
Внутри `gradlew --args="..."` дополнение не применяется.

Для постоянного подключения добавить в `~/.bashrc` строку с абсолютным путём
к скрипту (заменить путь своим):

```bash
source "/путь/к/EnderLink/cli/completion/cli.bash"
```

Примеры: `cli con` + Tab дополняется до `cli connect`,
`cli send --f` + Tab — до `cli send --file`. Если вариантов несколько,
двойное нажатие Tab показывает их список при стандартных настройках Bash.

Справка: `cli --help`. Код завершения: `0` — обычный выход, `1` — ошибка
ввода-вывода, `2` — неверные аргументы.

TCP-режим предназначен для доверенной локальной сети: шифрование и аутентификация
в нём не реализованы. В iroh-режиме соединения шифруются и ID проверяется.
Если второй компьютер по TCP не подключается, проверить IP,
доступность порта в межсетевом экране и изоляцию клиентов Wi-Fi.

## Интерактивный интерфейс (первый прототип)

После `./gradlew :cli:installDist` запустите в терминале Linux или WSL:

```bash
./cli/build/install/cli/bin/cli tui
```

Сверху находятся панели мира и друзей и кнопки действий; снизу — строка команд
EnderLink с подсказкой. Кнопки и команды используют одно состояние. Это первый
этап: просмотр существующего хранилища и профиля, без публикации и передачи через
TUI. Обычные одноразовые команды, включая передачу, остаются доступны отдельно.

Команды внутри окна:

```text
repository "путь к существующему хранилищу"
world-status
profile "путь к существующему профилю"
friends
id
theme [mono|ender|btop]
help
clear
exit
```

`repository` выбирает репозиторий EnderLink с `.enderlink`, а не исходный мир или
Minecraft `saves`. `profile` меняет выбранный путь в памяти; `friends`/`id` читают
существующий профиль с сохранением его блокировки. Новый ключ автоматически не
создаётся. Профиль по умолчанию тот же, что у обычного CLI. Если он занят GUI или
другим процессом, сначала закройте тот процесс или выберите другой профиль.
Список друзей показывает последний прочитанный снимок, а не присутствие в сети.
Состояние мира относится к опубликованной версии; изменения в `saves` не проверяются.

F2 переводит фокус в строку; Shift+Tab — обратно к элементам панели. В строке Tab
дополняет имя команды; стрелки вверх/вниз перебирают историю текущего сеанса.
Enter выполняет команду, Esc или Ctrl+C очищают ввод. Ctrl+W удаляет слово слева
от курсора. F10, Ctrl+Q или `exit` закрывают окно, в том числе во время чтения данных.
Если F10 открывает меню самого терминала, используйте Ctrl+Q, кнопку «Выход» или
`exit`: перехваченное терминалом нажатие не поступает приложению.
Мышь включена для нажатия кнопок, подсветки при наведении и выбора фокуса
в совместимых терминалах.
Кнопки оформлены рамками; текстовый курсор на них скрыт. Панели мира и друзей
растягиваются вместе с окном, в том числе при нечётном числе строк и колонок.
Кнопки расположены компактно слева в два ряда.
Статус выполнения («Готово», «Ошибка» или ожидание) расположен под блоком
«Команда EnderLink»; подробности ошибок выводятся в «Результат».
Для путей с пробелами используйте кавычки; обратная косая черта остаётся буквальной.
Системные команды и shell-подстановки не выполняются. История не сохраняется на диск.

Кнопка «Тема» открывает выбор оформления. То же действие доступно командами:

- `theme mono` — исходная монохромная тема, используется по умолчанию;
- `theme ender` — Ender / Void: обсидиановый фон, фиолетовый фокус, бирюзовые заголовки;
- `theme btop` — оформление в стиле btop с холодными рамками и зелёными акцентами.

`theme` без аргументов показывает текущую тему и варианты; Tab дополняет её имя.
Оформление меняется сразу, введённый текст сохраняется. Выбор записывается в
`~/.enderlink/cli.properties` и применяется при следующем запуске. В цветных темах
кнопки выделяются заливкой при фокусе и наведении, «Выход» — красным. Для точного
отображения палитр нужен терминал с поддержкой RGB (true color).

Запускайте собранный скрипт напрямую, в терминале UTF-8. Минимальный размер — 80×24
символа. При меньшем размере вместо панелей появляется сообщение с текущим и
требуемым размером; ввод и кнопки временно недоступны, F10 и Ctrl+Q работают.
После увеличения окна панели, данные, текст команды и фокус восстанавливаются.
Перенаправленный ввод/вывод и `TERM=dumb` отклоняются до перехода в полноэкранный режим.
Справка `cli tui --help` работает и без терминала. Нативная консоль Windows в этом
прототипе пока не подключена; вместо отдельного графического окна выводится ошибка.

Тесты используют виртуальный терминал и проверяют выход и восстановление режима
после ошибки. Поведение реальных терминалов, изменения размера окна и клавиш ещё
нужно проверить вручную; Windows-адаптер, дополнение путей/имён и общие операции
агента — следующие этапы. Решение по UX: [задача CLI/TUI](../tasks/task_cli_tui.md).
