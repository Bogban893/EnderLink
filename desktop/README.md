# EnderLink Desktop

Настольный интерфейс для Minecraft Java миров. Работает на Java 21 и использует то же
хранилище версий и тот же протокол, что CLI. Запуск из исходников:

```bash
./gradlew :desktop:run
```

Для отдельного запуска соберите дистрибутив:

```bash
./gradlew :desktop:installDist
desktop/build/install/desktop/bin/desktop
```

В папке `desktop/build/install/desktop/` находятся исполняемый скрипт и все нужные JAR.
На другом компьютере нужна Java 21. Для Linux необходима графическая сессия.

## Первый мир

1. При первом запуске Desktop создаёт библиотеку `~/.enderlink/worlds` и пустое
   хранилище для первого мира. На вкладке **Принять мир** один раз проверьте путь к
   `saves` именно вашего лаунчера; выбранный путь сохраняется.
2. Для уже существующего мира на вкладке **Обзор** нажмите **Импортировать закрытый мир**,
   выберите его папку и укажите UUID аккаунта, которым играли. Для следующего
   входящего мира нажмите **Новый мир для приёма**. Каждый мир получает отдельное
   хранилище с постоянной папкой и отображается в библиотеке Обзора.
3. На вкладке **Отправить мир** можно выбрать папку *закрытого* одиночного мира и указать
   UUID Minecraft-аккаунта, которым вы играли в нём. Для старого формата приложение
   сохраняет актуальное состояние владельца в файле его UUID внутри новой версии.
   Исходный мир остаётся неизменным. Если версия уже опубликована в хранилище,
   поле источника можно оставить пустым.
4. На компьютере друга откройте **Принять мир**, проверьте папку `saves` выбранной
   установки Minecraft Java, имя папки мира и UUID аккаунта, которым друг будет
   играть одиночно, затем нажмите **Ждать мир**.
5. Отправитель выбирает друга или TCP адрес и нажимает **Отправить мир**.

После получения манифеста на компьютере друга Desktop показывает предложение с
источником, ID мира и версии, числом файлов и размером. Нажмите **Да**, чтобы начать
приём блоков; **Нет**, закрытие окна и отсутствие ответа в течение 55 секунд отклоняют
предложение. До ответа входящая версия не записывается в хранилище и не устанавливается
в `saves`. При iroh в предложении указан проверенный ID выбранного друга; TCP не
проверяет личность отправителя и предназначен только для доверенной локальной сети.
Публичного поиска участников и аккаунтов пока нет: друзья обмениваются ID вручную.

Чтобы перенести библиотеку, нажмите **Перенести библиотеку** на Обзоре и выберите
другую папку, отдельную от `saves`. Desktop явно запросит подтверждение, скопирует
управляемые репозитории и проверит их перед переключением. Потребуется место под
полную копию; старая библиотека остаётся резервной копией и не удаляется. Уже
выбранные вручную внешние репозитории не перемещаются. При обновлении с прежней
версии Desktop сохраняет выбранное внешнее хранилище и не переносит его молча.
Имя папки в `saves` и сведения для обновления запоминаются отдельно для каждого мира.

Для передачи через интернет каждый участник добавляет ID другого на вкладке **Друзья**.
Профиль общий с CLI (`~/.enderlink/iroh-test`), поэтому одновременно использовать один
профиль в CLI и Desktop нельзя. Для TCP адреса оба участника выбирают одинаковый порт;
получатель должен быть доступен по сети.
При наличии своего координатора укажите его HTTPS-адрес на вкладке **Друзья** у
обоих участников. Desktop сообщает, видит ли координатор друга и готов ли тот
принимать мир, затем использует найденные адреса для защищённого соединения iroh.
Если координатор недоступен, приложение пробует обычный поиск iroh. Пустой адрес
оставляет прежнее поведение. [Установка и границы сервиса](../coordinator/README.md).

После приёма проверенная версия автоматически появляется как обычный мир в папке
`saves`, то есть в списке одиночной игры Minecraft. При следующем приёме EnderLink
передаёт только отсутствующие блоки по 256 КиБ и обновляет ту же папку. Если мир уже
был в `saves`, но хранилище EnderLink на этом компьютере пустое, приложение сначала
кеширует его блоки; отправитель также передаёт отпечаток предыдущей версии, чтобы
проверить, что обновляется именно этот мир. Изменённый локально или открытый в игре
мир не заменяется. Для старого формата EnderLink подставляет в установленную копию
данные выбранного UUID, а если игрока ещё не было — убирает встроенное состояние
прежнего владельца. Для нового формата переключает `singleplayer_uuid`. Опубликованная
версия и файлы других игроков не меняются. Полученный мир появляется в библиотеке
на вкладке **Обзор**. Выберите его там, если переключались на другой мир. Кнопка
**Отправить эту версию** открывает
отправку без повторного импорта. После игры на получателе закройте мир в Minecraft,
на вкладке отправки нажмите **Взять мир после игры из saves**, укажите свой UUID и
отправьте его: приложение опубликует изменённую копию как новую версию. Если оставить
источник пустым, EnderLink проверит установленные копии этого мира в указанной на
вкладке приёма папке `saves` и не отправит старую версию при обнаружении изменений.
Если мир находится в другой установке Minecraft, сначала выберите её папку `saves`
на вкладке приёма. Папка источника не изменяется.
После закрытия Minecraft можно нажать **Обновить Minecraft**,
если установка не завершилась после получения. Папку `saves` можно выбрать вручную
для лаунчера с собственным каталогом игры.

### Разные UUID хоста и гостя в LAN

Если лаунчер использует UUID аккаунта в одиночной игре, а при входе к другу сервер
назначает UUID по нику, заполните **Ваш точный ник для LAN-игры с другим UUID**.
Укажите свой ник с точным регистром и UUID аккаунта, которым открываете мир одиночно.
Эти поля общие для импорта, отправки и приёма и сохраняются между запусками.
Каждый участник указывает свои данные.

При публикации EnderLink обновляет LAN-профиль из актуального профиля хоста.
При установке существующий LAN-профиль имеет приоритет и копируется в профиль
аккаунта для одиночной игры. Переносятся весь NBT игрока, достижения и статистика.
Действия выполняются в подготовленных копиях, предыдущие версии доступны в истории.
Если `singleplayer_uuid` исходного мира отличается от введённого UUID аккаунта,
публикация с LAN-ником останавливается и сообщает UUID фактического владельца.

Включайте эту связь только для собственных профилей одного игрока. Для соединения
с проверкой аккаунта оставьте ник пустым. Настройка применяется при следующей
публикации или установке мира. Уже появившийся пустой профиль требует восстановления
из сохранённого профиля с вещами перед продолжением игры.

Если старый мир хранит данные владельца только в `level.dat`, на вкладке **Обзор** можно
указать UUID обычного Minecraft аккаунта и нажать **Перенести вещи**. Это создаёт отдельный
файл игрока в новой версии. Исходный одиночный мир не меняется. Для новых форматов мира,
где данные уже лежат в `players/data`, этот шаг не нужен. Эта отдельная кнопка
остаётся для одноразового переноса владельца при серверном сценарии.

## Сервер

На вкладке **Сервер** выберите папку с `eula.txt` и, при необходимости,
`server.properties`, затем файл `server.jar`. EULA принимается пользователем вручную;
в свойствах сервера нужны `online-mode=true` и `level-name=world`. Каждый запуск создаёт
отдельную папку в `enderlink-sessions`, сохраняя копию мира и журнал. Кнопка
**Сохранить и остановить** публикует новую версию. При закрытии окна с работающим
сервером приложение предложит сначала сохранить и остановить его.

Интерфейс показывает состояние и ход операции. Отменить ожидание или передачу можно
кнопкой **Отменить**; повторная передача использует уже сохранённые блоки. Если
полученная версия расходится с активной, обе версии сохраняются и приложение предлагает
явно выбрать входящую ветку.
Строка состояния показывает прошедшее время текущего этапа. Ожидание входящего
подключения длится до отмены; после подключения отправитель ждёт готовности
получателя до 60 секунд, затем каждая сторона ждёт очередные данные до 300 секунд.
Отсчёт 60 секунд включает подтверждение входящего мира; диалог закрывается через
55 секунд, чтобы отказ успел дойти до отправителя.
Это не общий предел длительности передачи. В Desktop эти пределы фиксированы.
При сетевой ошибке окно показывает причину, действие, ID операции и путь к
локальному файлу `~/.enderlink/diagnostics/<ID>.log` с технической причиной.
Если файл создать нельзя, причина выводится в stderr процесса Desktop. Отказ
подключения или таймаут не подтверждает, что друг offline.

## Структура модуля

Исходники находятся в `src/main/kotlin/org/enderlink/desktop`:

```text
Main.kt         запуск приложения и настройка Swing
ui/             окно, навигация и форматирование вывода
  screens/      обзор, отправка, приём, сервер и друзья
  components/   оформление, компоновка, общие элементы и масштабирование
  dialogs/      выбор файлов и каталогов, сообщения и подтверждения
presentation/   действия пользователя, фоновые задачи, прогресс и серверная сессия
i18n/           загрузка переводов и форматирование сообщений
settings/       чтение и запись desktop.properties
transfer/       передача мира и закрытие сетевых ресурсов при отмене
minecraft/      проверка и установка мира в saves
```

Экраны создают элементы Swing и вызывают переданные обработчики действий.
`DesktopController` связывает их с операциями; `ServerController` владеет серверной
сессией. `DesktopJobs` выполняет длительную работу вне EDT и возвращает результаты
в EDT. Окно владеет таймером проверки сервера и останавливает его при закрытии.
Форматы миров и сетевые протоколы остаются в `core`.

Тесты повторяют структуру пакетов в `src/test/kotlin`. Проверка модуля:

```bash
./gradlew :desktop:test
```

## Оформление и состояния

Desktop использует тёмные обсидиановые и фиолетовые поверхности с зелёным
акцентом эндер-жемчуга. Навигация снабжена пиксельными значками. Во время
ожидания полоса передачи движется, при передаче показывает процент, а результат
отмечается текстом и цветом. Кнопки, переключатели и поля показывают фокус при
управлении с клавиатуры. Масштаб интерфейса меняется вместе с размером окна.

## Выбор файлов и папок

Кнопки выбора исходного мира, хранилища, `saves`, настроек сервера и `server.jar`
открывают системный диалог через [FlatLaf SystemFileChooser](https://www.formdev.com/flatlaf/system-file-chooser/).
Поддерживаются Windows 10+, macOS 10.14+ и Linux с GTK 3, включая обычные графические
установки Ubuntu. Нативные библиотеки входят в дистрибутив desktop; отдельная
установка FlatLaf не нужна. Компонент используется только для выбора файлов.

Если платформа не поддерживается, GTK 3 или нативная библиотека недоступны,
используется запасной Swing-диалог. Принудительно включить его для диагностики
можно JVM-параметром `-Dflatlaf.useSystemFileChooser=false`.
Системные кнопки и элементы окна могут использовать язык ОС.

Диалог папки начинает работу с пути из соответствующего поля или с последней
выбранной папки для этого назначения. Если введённый путь ещё не существует,
откроется ближайший существующий родительский каталог. Отмена оставляет путь
без изменений. Путь можно вставить в редактируемое поле EnderLink; для смены
папки библиотеки используйте кнопку переноса. При выборе проверяются права,
`level.dat` для исходного мира и разделение папок `saves` и хранилища.
При выборе `server.jar` сохраняется фильтр JAR-файлов и проверяется файл.
Выбор папки сам по себе не публикует и не передаёт мир.

## Язык интерфейса и тексты

По умолчанию интерфейс русский. Язык выбирается при запуске через JVM-параметр
`enderlink.language`: `ru` или `en`; для неподдерживаемого языка используется русский.
Например, после сборки `:desktop:installDist` запуск на английском в Linux/macOS:

```bash
JAVA_OPTS="-Denderlink.language=en" desktop/build/install/desktop/bin/desktop
```

В Windows PowerShell:

```powershell
$env:JAVA_OPTS = "-Denderlink.language=en"
.\desktop\build\install\desktop\bin\desktop.bat
```

Для смены языка нужен перезапуск. Сообщения, поступающие из `core`, `agent`, JVM
и сетевых библиотек, сохраняют исходный язык; их диагностические причины не переводятся.

Тексты desktop находятся в `src/main/resources/messages.properties` (русский)
и `messages_en.properties` (английский). Файлы имеют кодировку UTF-8. Чтобы изменить
подпись, достаточно отредактировать значение соответствующего ключа и пересобрать
приложение. Например:

```properties
transfer.recipientAddress.required=Введите адрес получателя
transfer.connecting=Подключаемся к {0}:{1}…
```

Kotlin-код обращается к каталогу через `messages.text("transfer.connecting", host, port.toString())`.
Храните сообщение целиком, передавая переменные как параметры `{0}`, `{1}` и т. д.
В переводе порядок параметров можно менять. Шаблоны используют `MessageFormat`:
литеральный апостроф записывается как `''`, перенос строки — как `\n`.
Числовое форматирование задаётся в шаблоне, например `{0,number,0.0}` для объёма.
ID, порты и счётчики без группировки разрядов передавайте строками.

При добавлении текста внесите одинаковый ключ в оба файла. Проверки `MessagesTest`
сверяют наборы ключей, параметры и корректность шаблонов. Имена файлов, значения
настроек, команды сервера и сетевые идентификаторы в переводы не переносятся.
