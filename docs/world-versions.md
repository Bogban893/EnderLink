# Локальные версии мира

`core/world` работает только с каталогами. Перед сканированием нужно закрыть мир в Minecraft или остановить сервер и не менять файлы до завершения публикации. Проверка размера во время чтения обнаруживает часть случайных изменений, но не заменяет согласованный снимок файловой системы.

## Общие поля форматов 1 и 2

- `worldId` — UUID в нижнем регистре; он остаётся одним для всех версий мира и не зависит от имени каталога.
- Манифест содержит **все** записи, кроме корневого каталога. Пустые каталоги включаются. Отсутствие пути в следующем манифесте означает удаление.
- Путь относительный; разделитель `/`. Записи отсортированы по лексикографическому порядку строк Kotlin, родительский каталог должен предшествовать дочерней записи. Повтор путей запрещён.
- Для файла записываются размер в байтах и SHA-256 содержимого. Файл читается потоково. Ссылки и специальные файлы отвергаются; ссылки не обходятся. В пути запрещены пустые компоненты, `.`, `..`, обратная косая черта, двоеточие, управляющие символы и имена, опасные для Windows.
- `treeHash` — SHA-256 канонической последовательности: строка `enderlink-tree-v1`, число записей, затем для каждой записи путь, тип (0 — каталог, 1 — файл), а для файла размер и строка хеша. Строка кодируется как 32-битная длина в байтах и UTF-8; целые числа — big-endian. Идентификатор имеет вид `sha256:<64 строчных hex-символа>`.
- В формате 1 `versionId` — SHA-256 последовательности: строка `enderlink-version-v1`, число `formatVersion`, строка `worldId`, признак наличия родителя, строка `parentVersionId` при его наличии, строка `treeHash`. Поле `versionId` не хеширует само себя. Две ветки могут иметь одинаковый `treeHash` и разные `versionId`.

## Формат 2 — файловые блоки

Новые версии создаются в формате 2; существующие манифесты и объекты формата 1 читаются без миграции. Каждый файл содержит упорядоченный список `{hash, size}`. Схема `fixed-262144-v1`: блоки по 262144 байта от начала файла, последний может быть короче; пустой файл имеет пустой список. Каждый блок адресуется SHA-256 своих байтов. `treeHash` по-прежнему зависит от полного состава файлов, их размеров и полных хешей, поэтому одинаковые деревья форматов 1 и 2 имеют одинаковый `treeHash`.

`versionId` формата 2 — SHA-256 последовательности: строка `enderlink-version-v2`, число `2`, `worldId`, признак и ID родителя, `treeHash`, строка `fixed-262144-v1`, число файлов, затем для каждого файла путь, число блоков и упорядоченные пары `hash`/`size`. Строки и числа кодируются так же, как для `treeHash`. Это связывает ID версии с точной схемой разбиения. Схема не меняется молча между версиями.

Дисковый манифест использует кодировку `ELW1` и хранит после хеша файла число блоков и их пары только в формате 2. Протокол `ELW2` передаёт заголовок файла и число блоков, затем отдельные сообщения с описанием каждого блока; сообщение не превышает лимит `Connection` в 1 МиБ.

Тесты W1: `./gradlew :core:test --tests org.enderlink.world.WorldManifestTest`.

## Локальное хранилище и обновление (W2)

`WorldRepository(base)` хранит рабочий мир в `base/world`, метаданные в `base/.enderlink`:

```text
.enderlink/
  active                 # ID текущей версии
  versions/<id>.manifest # полный манифест
  objects/<sha256>       # неизменяемый блок формата 2 или файл формата 1
  staging/               # сборка до активации
  previous/              # рабочая копия перед последним переключением
```

Пример локального сценария: первый участник вызывает `publish(repository.workingDirectory)`, второй — `importFrom(firstRepository, manifest)` и `activate(manifest)`. После игровой сессии первый снова вызывает `publish`, второй импортирует новую версию и активирует её. `plan` показывает добавленные, изменённые и удалённые пути. Если дерево не изменилось, `publish` возвращает текущую версию без новой записи. Одинаковые блоки сохраняются одним объектом по SHA-256; старые объекты остаются для `checkout(versionId)`.

Перед активацией все объекты сверяются по размеру и SHA-256, дерево собирается в `staging` и сверяется с манифестом. Затем каталоги переключаются атомарными переименованиями на одном томе. Маркер `pending` позволяет `recover()` после перезапуска завершить уже проверенное переключение или вернуть прежний `world`. При несовпадении родителя возникает `WorldConflictException`; обе ветки остаются в `versions` и `objects`. Неопубликованные изменения рабочего мира также блокируют переключение.

Фиксированные блоки повторно используются, когда их байты остаются на тех же смещениях. Сдвиг внутри файла может изменить все последующие блоки; алгоритм rsync и разбор `.mca` требуют отдельного сравнения на реальных мирах. Сборка мусора ещё не выполняется: объекты истории не удаляются автоматически. Для атомарного переименования `world`, `staging` и `.enderlink` должны быть на одном томе. Пиковое дополнительное место может включать старую рабочую копию, новую сборку и новые объекты.

Тесты W2: `./gradlew :core:test --tests org.enderlink.world.WorldRepositoryTest`.

## Передача версии (локальная проверка I1)

`core/worldtransfer` передаёт версию поверх `Connection`, который реализован для TCP и iroh. Протокол имеет отдельный заголовок `ELW2`: отправитель посылает полный манифест по записям и блокам; получатель проверяет его и отвечает для каждого уникального объекта `HAVE` или `NEED`. После `NEED` объект идёт сообщениями до 256 КиБ и проверяется по размеру и SHA-256. Подтверждение всей версии отправляется только после проверки собранного дерева и активации. Повторный запуск после разрыва использует уже проверенные блоки; незавершённый блок передаётся заново. При конфликте обе ветки сохраняются, но рабочая версия не переключается. Если получатель не имеет предка версии, он может принять текущую версию как первую локальную копию мира; история до неё остаётся только у отправителя.

Независимый протокол не меняет `send --directory` и не связывает `core/world` с сетевыми классами. Команды и пример запуска описаны в [руководстве CLI](../cli/README.md#версии-закрытого-мира). Локальные интеграционные тесты: `./gradlew :core:test --tests org.enderlink.worldtransfer.WorldTransferTest` и `./gradlew :core:test --tests org.enderlink.network.iroh.WorldIrohTransferTest`. Явный выбор сохранённой ветки: `world-checkout --repository <каталог> --version <ID>`.

Граница текущей реализации: блоки фиксированы по смещению; экономия на сдвигах и реальных `.mca` пока не измерена. Сценарий на двух физических компьютерах, разные реальные сети и открытие копии в Minecraft пока не проверены.

## Локальный замер фиксированных блоков

Воспроизведение после `./gradlew :cli:installDist`: `./scripts/benchmark-world-transfer.sh`. Скрипт создаёт детерминированный файл `region.mca` размером 8 МиБ, пустой каталог и маленький `level.dat`, проводит первую передачу, повтор без изменений, меняет один байт внутри одного блока и затем добавляет 4 МиБ новых данных. TCP идёт по `127.0.0.1`. Скрипт сохраняет логи и показывает размер хранилища, рабочей и предыдущей копий. Данные псевдослучайны и не являются настоящим миром Minecraft.

Результат запуска 9 ноября 2026 года на локальной машине; время и RSS зависят от машины. Накладные байты включают метаданные и рамки сообщений отправителя, но не ответы получателя.

Публикация занимала 0,21–0,26 с с пиком RSS 132 088–174 156 КиБ. Пиковое дополнительное место — разница между максимальным и исходным размером каталога получателя, выборка каждые 5 мс по видимым размерам файлов. Короткий пик между выборками может быть пропущен; выделенные файловой системой блоки отдельно не измерялись. После операций рабочая копия занимала 8 388 613 Б до добавления файла и 12 582 917 Б после; `staging` был пуст, предыдущая копия после обновления занимала 8 388 613 Б. Повреждение блока и отказ записи объекта с ошибкой «нет места» проверяются тестами: активная версия сохраняется, временный объект удаляется, повторная передача завершается. Реальный заполненный диск и открытие мира в Minecraft ещё требуют проверки.
