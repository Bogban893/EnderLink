# Группа и роли при обмене одиночным миром

Решение для B15/B16, 24 ноября 2026 года. Оно описывает будущий групповой
сценарий и пока не включает сетевое применение прав. Текущая прямая передача
мира в Desktop остаётся обменом между двумя друзьями.

## Участники и чат

Группа имеет случайный ID, одного текущего хоста и набор приглашённых ID iroh.
Хост отправляет приглашение другу, друг принимает его явно. Участник может выйти;
если выходит хост, он сначала передаёт роль или закрывает группу. Список участников
и роли видны всем членам. Приглашение не даёт права скачать мир до назначения роли
«принимающий» и отдельного подтверждения конкретной версии мира. Чат доставляет
сообщения только подключённым участникам; историю и сообщения для offline-участников
в первую версию не сохраняем. Игрок получает сообщения чата и служебные события
группы, но не манифесты и блоки мира.

## Права на мир

| Роль | Отправка мира | Приём мира | Чат | Запрос смены роли |
|---|---:|---:|---:|---:|
| Хост | Да, выбранному принимающему | Нет | Да | Предлагает |
| Принимающий | Нет | Да, после подтверждения предложения | Да | Подтверждает или отклоняет |
| Игрок | Нет | Нет | Да | Может попросить хоста о смене роли |

Роль связана с ID EnderLink/iroh; UUID Minecraft нужен только для данных игрока и
не подтверждает право передачи. Права должны проверяться при каждой сетевой
команде и выдаче данных в общем агенте, а не только в Desktop. Пока агента с
локальным API нет, таблица не применяется к существующему прямому протоколу.

Текущий хост выбирает одного участника как принимающего и предлагает передачу
роли. Новый хост подтверждает её после проверки полной версии мира. До этого
старый хост остаётся единственным хостом. Во время активной передачи новая смена
роли не допускается; повтор предложения с тем же ID операции возвращает текущее
состояние. При отказе, обрыве или конфликте старая роль сохраняется, а обе
проверенные ветки мира остаются в хранилищах. После подтверждения старый хост
становится принимающим, чтобы можно было вернуть мир; остальные роли не меняются.
Одновременные назначения двух хостов отвергаются по версии состояния группы.

Реализация требует общего процесса агента и аутентифицированного группового
протокола: отдельные Desktop и CLI сейчас открывают профиль независимо и не могут
надёжно разделять одну группу. Внедрение прав поверх одной только кнопки GUI
создало бы обход, поэтому B15/B16 остаются открытыми до этого этапа.
