# Локальный Vanilla сервер

Сначала опубликуйте закрытый мир через `cli world-publish --source <мир> --repository <репозиторий>`.
При необходимости выберите сохранённую версию командой `cli world-checkout`.
Проверьте, что серверная Java и `server.jar` соответствуют версии Minecraft.

Подготовьте отдельный каталог сервера. Vanilla сервер требует принятия его EULA:
поместите в этот каталог `eula.txt` с `eula=true` после ознакомления с условиями.
Если используете `server.properties`, значение `level-name` должно быть `world`.
Агент требует `online-mode=true`, если этот параметр задан: так UUID игроков
остаётся одинаковым при смене хоста и файлы данных игрока не раздваиваются.
Если в старом одиночном мире данные владельца встроены в `level.dat`, агент
предупредит перед запуском сервера. Проверьте инвентарь владельца в тестовой
сессии: автоматический перенос этих данных в файл UUID ещё не реализован.
Каталог `world` в папке сервера должен отсутствовать: агент скопирует туда
проверенную активную версию, сохранив рабочий мир репозитория отдельно.

```bash
./gradlew :agent:installDist
./agent/build/install/agent/bin/agent host \
  --repository ./my-world-repo \
  --server-dir ./server-session \
  --jar ./server.jar \
  --version 'sha256:<ID>'
```

В консоли работают `status`, `save` и `stop`. `save` отправляет `save-all flush`.
`stop` сначала отправляет сохранение, затем команду остановки и ждёт до 120 секунд.
После выхода сервера с кодом 0 агент публикует содержимое `server-session/world`
новой версией. Если сервер завершился с ошибкой или не остановился вовремя,
мир остаётся в этом каталоге для ручной проверки. Журнал процесса сохраняется
в `server-session/enderlink-server.log` и одновременно выводится в консоль.

Для следующей игровой сессии используйте новый пустой каталог сервера.
Настоящий `server.jar` и подключение Minecraft-клиента требуют отдельной
проверки на машине пользователя; локальный тест модуля использует тестовый процесс.

## Работа без открытой консоли

`agent host-service` принимает те же параметры, что `agent host`, но не читает
stdin. Запускайте его под менеджером служб, который сохраняет вывод процесса
и отправляет ему `SIGTERM` при остановке. Агент отправит серверу `save-all flush`
и `stop`, дождётся завершения и опубликует новую версию. Если сервер завершится
сам с кодом 0, агент тоже опубликует мир; при ошибке оставит копию в каталоге
сессии для проверки. Процесс остаётся на переднем плане, чтобы менеджер служб
мог отслеживать его состояние.

```bash
./agent/build/install/agent/bin/agent host-service \
  --repository ./my-world-repo --server-dir ./server-session \
  --jar ./server.jar
```

Для systemd используйте `Type=simple`, [`KillMode=mixed`](https://www.freedesktop.org/software/systemd/man/262/systemd.kill.html) (чтобы `SIGTERM`
сначала получал агент, а оставшиеся процессы завершались после его выхода или
таймаута) и `TimeoutStopSec`,
достаточный для остановки сервера и публикации большого мира. Остановка
`systemctl stop` запускает shutdown hook JVM. Для следующей сессии нужен новый
пустой `--server-dir`; автоматический рестарт с прежним каталогом не настроен.
`SIGKILL`, аварийное отключение питания и принудительное закрытие процесса не
дают выполнить сохранение: в этом случае проверяйте `server-session/world`.

## Игровой туннель через iroh

Оба участника должны заранее добавить ID друг друга командами `cli add` и
использовать свои профили iroh. На компьютере с запущенным Vanilla сервером:

```bash
./agent/build/install/agent/bin/agent tunnel-host --peer friend --target-port 25565
```

На компьютере игрока:

```bash
./agent/build/install/agent/bin/agent tunnel-join --peer host --local-port 25565
```

В Minecraft игрок подключается к `127.0.0.1:25565`. Локальный слушатель
доступен только на loopback адресе. Если игровой сервер слушает другой адрес,
укажите `--target-host`; если локальный порт занят, измените `--local-port`.
Для отдельного профиля используйте `--profile`, для заданного relay на стороне
игрока — `--relay`. Туннель передаёт байты TCP без изменения игрового протокола.
После закрытия игрового соединения обе команды ждут следующего подключения;
одновременно обслуживается один игровой клиент. Завершение агента — Ctrl+C.
Локальный тест проверяет передачу байтов и второе подключение. Реальный Minecraft
и разрыв iroh между двумя компьютерами требуют проверки пользователем.
