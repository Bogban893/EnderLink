# Локальный Vanilla сервер

Сначала опубликуйте закрытый мир через `cli world-publish --source <мир> --repository <репозиторий>`.
При необходимости выберите сохранённую версию командой `cli world-checkout`.
Проверьте, что серверная Java и `server.jar` соответствуют версии Minecraft.

Подготовьте отдельный каталог сервера. Vanilla сервер требует принятия его EULA:
поместите в этот каталог `eula.txt` с `eula=true` после ознакомления с условиями.
Если используете `server.properties`, значение `level-name` должно быть `world`.
Каталог `world` в папке сервера должен отсутствовать: агент скопирует туда
проверенную активную версию, сохранив рабочий мир репозитория отдельно.

```bash
./gradlew :agent:installDist
./agent/build/install/agent/bin/agent host \
  --repository ./my-world-repo \
  --server-dir ./server-session \
  --jar ./server.jar \
  --version 'sha256:<ID>'
```

В консоли работают `status`, `save` и `stop`. `save` отправляет `save-all flush`.
`stop` сначала отправляет сохранение, затем команду остановки и ждёт до 120 секунд.
После выхода сервера с кодом 0 агент публикует содержимое `server-session/world`
новой версией. Если сервер завершился с ошибкой или не остановился вовремя,
мир остаётся в этом каталоге для ручной проверки. Журнал процесса сохраняется
в `server-session/enderlink-server.log` и одновременно выводится в консоль.

Для следующей игровой сессии используйте новый пустой каталог сервера.
Настоящий `server.jar` и подключение Minecraft-клиента требуют отдельной
проверки на машине пользователя; локальный тест модуля использует тестовый процесс.
